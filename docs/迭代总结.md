## 三、关键发现（实测得出，价值最高）

### 1. `enable_thinking: false` —— 单点收益最大

Qwen3 系列（含硅基免费版）默认开启思考模式，对摘要/翻译类任务纯属浪费：

| 指标 | 思考模式 | 关闭后 | 提升 |
|------|---------|--------|------|
| 延迟 | 19.5s | **0.71s** | **27×** |
| tokens | 393 | **19** | **-95%** |

**两个字回复消耗 393 tokens**——这类"思考税"是隐形 Token 大户。

### 2. 免费模型目录变动频繁，禁止硬编码模型名

首次配置写的模型（`llama-3.1-8b-instant`、`meta-llama/llama-3.3-70b-instruct:free`）**均已下架**。
→ 上线前必须用 `/v1/models` 核实；配置按**能力**而非版本号选型。

### 3. 境外免费池在国内必须走代理，延迟代价显著

| Provider | 网络 | 实测延迟 |
|---------|------|---------|
| DeepSeek | 国内直连 | 1.0s |
| Groq | 经梯子 | 12-24s |
| **硅基流动** | **国内直连** | **0.7-2.0s** |

→ **结论**：国内环境下免费池首选**硅基流动**；境外池只做兜底。
→ **策略**：短请求直连（不为省几分钱等 20 秒）；长输入大 token 请求才走免费池。

### 4. 代理是单点，必须常驻 + 可秒回滚

接入后 Hermes 全部流量经代理 → 代理挂 = Hermes 挂。
→ launchd `KeepAlive` 常驻 + `switch.sh`/`rollback.sh` 一键切换。

## 五、接入后性能验证（2026-09-28 22:50）

**用户核心要求：保证性能不退化。**

| 场景 | 接入后延迟 | 走向 | 对比接入前 |
|------|-----------|------|-----------|
| 短请求（无工具）| 0.81s | DeepSeek 直连 | **无变化** ✅ |
| 流式首字（Hermes 会话）| 0.49s | DeepSeek 直连 | **无变化** ✅ |
| 带工具请求（Agent 主链路）| 0.79-1.94s | DeepSeek 直连 | **无变化** ✅ |
| 长输入压缩（4125 tokens）| 2.19s | 硅基免费池 | 由付费转为 ¥0（延迟可接受）|

**结论**：同路径延迟与接入前一致；只有长输入任务转移至免费池（省 token 且延迟可控）。

### 接入过程中修复的两个性能隐患

**① 兜底 provider 被误熔断**
- **现象**：`deepseek banned_for: 599`（熔断 10 分钟）
- **危害**：兜底被熔断 → 请求 fallback 到慢的免费池 → **性能反而退化**
- **修复**：config 加 `no_breaker: true`，熔断器 `record(exempt=True)` 只统计不熔断

**② 流式请求为观测盲区**
- **现象**：微信会话（Hermes 主链路全部是流式）延迟记录为 `None`
- **危害**：无法评估真实性能，无法发现退化
- **修复**：流式分支补 `latency` 记录 + 熔断统计

### 新增运维接口

- `POST /admin/reset_breaker` — 手动重置熔断（性能排查用）
- 健康检查 `/health` 现在暴露各 provider 的熔断状态

## 七、经验沉淀（可复用到其他 Agent 项目）

1. **能算的别让模型猜**（与 CAN/Modbus 工具同理）：能用规则判定的路由不调模型
2. **按能力选型，不按版本号**：免费模型目录月月变，写死必翻车
3. **省 token 不能牺牲体验**：延迟是隐性成本，"省钱等 20 秒"用户会跑
4. **红线优先**：免费层数据用于训练 → 分级隔离必须先于省钱
5. **单点必须可回滚**：改全局配置前先备份 + 准备一键恢复
